# LLM 실패 진단 및 불완전 게시 차단

- 모델 gpt-6.1-sol 및 600초 제한은 유지한다. 제한 추가 확대나 무조건 재시도는 하지 않는다.
- 공통 호출은 JSON 모드로 실행해 프롬프트 echo를 억제하고, 호출 ID·프로세스 ID·시작/종료 UTC·경과 시간·입력 길이·동시 실행 수·실패 종류를 구조화해 기록한다. stderr는 민감정보를 제거하고 제한된 길이만 기록한다.
- 필수 항목 분석은 strict 모드로 CLI 타임아웃·실패·빈 응답·비정상 JSON·스키마를 명시적 LLM 예외로 전달한다. 날짜 판정은 실제 bool만 허용하고 번역·요약은 문자열만 허용한다. 선택 다이어그램은 기존 빈 문자열 폴백을 유지한다.
- 필수 범위: 수록 대상 항목의 제목 번역, 본문 150자 이상인 블로그·논문·GitHub 항목의 요약. 커뮤니티는 번역만 요구한다. 정상적으로 날짜 범위 밖으로 판정된 글은 실패가 아니다.
- 필수 분석 실패나 오늘의 해석 누락 시 HTML/Git/Slack 게시 전에 중단한다. 실패 발생 시 대기 중 작업을 취소한다.
- LLM 타임아웃·비정상 응답과 필수 요약 누락을 주입해 게시 차단을 검증하고, 정상 모델 호출과 전체 테스트를 확인한다.
- 26일 기존 프로세스는 필수 요약 누락을 확인한 뒤 HTML·JSON을 체크포인트에 보관하고 게시 전에 중단했다. 남은 요약을 복구하고 새 실패 차단 정책으로 검증한 결과만 반영한다.

## 실측에 따른 운영 제한

현재 환경에서 4개 동시 호출은 모두 진단 제한 90초를 넘겼고, 단건의 정상 요약은 10~17초에 완료됐다. 동시 호출 직후 단건도 90초를 넘겼으므로 동시성만을 근본 원인으로 확정하지 않는다. 요청 압력을 줄이기 위해 요약과 SVG의 동시 LLM 실행 수를 1로 제한한다. 프로덕션 호출 제한 600초와 모델은 유지하며, 이후 호출 로그로 원인을 계속 구분한다.

## 원문 보존

Alibaba는 메뉴 main 대신 실제 markdown-body를 추출한다. arXiv 초록은 수집 시 600자에서 자르지 않고 보존하며, 분석 단계의 기존 1500자 입력 한도에서 제한한다. 이른 절단 때문에 원문 초록이 요약 대신 표시되거나 응답이 비는 경우를 줄인다.

테스트의 실패 주입 로그는 임시 디렉터리로 격리해 운영 배치 로그와 섞이지 않도록 한다.
