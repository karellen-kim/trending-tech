Kakao Tech
컨테이너처럼 쓰고, VM처럼 격리하기 4편 - IB 네트워크와 로컬 NVMe, vCPU 배치, 베어메탈 대비 성능
NAVER D2
GPU 학습용 VM에서 IB 네트워크와 GPUDirect RDMA를 사용하기 위한 장치 연결 방식을 다룬 글입니다.
- 앞선 3편에서는 Fabric Manager의 NVLink fabric partition을 DRA로 할당하고 VM에 연결했습니다.
- GPUDirect RDMA에서는 NIC가 GPU 메모리의 BAR 영역을 DMA로 읽고 써서 GPU 데이터를 호스트 메모리로 복사하는 과정을 생략합니다.
- 호스트의 /dev/infiniband 장치 파일은 VM에서 사용할 수 없어, IB NIC를 vfio-pci에 바인딩한 뒤 VFIO로 게스트에 직접 연결했습니다.
컨테이너처럼 쓰고, VM처럼 격리하기 3편 - Fabric Manager 파티션과 DRA를 이용한 GPU 할당
NAVER D2
Fabric Manager의 GPU 연결 규칙을 Kubernetes의 GPU 할당에 반영하고 VM에 연결하는 과정을 다룬 글입니다.
- GPU 8장 서버에서 2장을 할당할 때는 NVLink로 연결할 수 있도록 하드웨어가 허용한 GPU 조합을 골라야 합니다.
- 장치 플러그인으로는 원하는 GPU 조합을 보장하지 못해 DRA(동적 리소스 할당)로 전환하고 자체 드라이버를 만들었습니다.
- 네이버 클라우드의 B200 서버는 NVSwitch로 GPU 8장을 연결합니다. VM 환경에서는 NVSwitch를 호스트에 두는 Shared NVSwitch 모드를 사용하며, GPU 2장을 VM에 연결할 때 해당 조합의 Fabric Manager 파티션을 활성화합니다.
컨테이너처럼 쓰고, VM처럼 격리하기 2편 - GPU 패스스루 계층과 GPU 8장 VM의 부팅·메모리 구성
NAVER D2
Kata Containers의 VM에 GPU를 연결하는 계층과 GPU 8장을 연결했을 때 발생한 부팅·메모리 구성 문제를 다룬 글입니다.
- GPU 1장 연결은 업스트림 kata와 NVIDIA 도구로 구현했지만, 8장을 VM 하나에 연결하자 부팅 시간 초과, 요청보다 작은 VM 생성, 호스트 소켓 구조를 모르는 게스트의 메모리 할당 문제가 발생했습니다.
- 네이버 클라우드의 B200 서버는 GPU 8장, 컴퓨트 IB NIC 8개, 스토리지 IB NIC 2개, 로컬 NVMe 4장으로 구성되며, GPU와 컴퓨트 NIC는 PCIe 스위치마다 한 쌍씩 연결됩니다.
- GPU는 DMA 주소 변환과 메모리 접근 제한을 담당하는 IOMMU, 호스트 드라이버에서 GPU를 분리해 QEMU에 넘기는 VFIO, 컨테이너에 연결할 장치를 런타임에 알리는 CDI를 거칩니다.
