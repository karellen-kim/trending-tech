# 중첩 Codex 완료 이벤트와 자동 실행 셸 격리

유형: bugfix. 목표는 Orca가 외부 실행 종료까지 기다리고 동일 실행 영수증의 게시 결과를 보고하는 것이다.

## 발생 내역과 원인

- 10월 30·31일: Python이 수집 중 SIGTERM/143으로 종료됐으나 Orca는 내부 논문 선택 숫자만 남기고 completed로 기록했다.
- 11월 1일: oh-my-zsh 업데이트 입력 질문 뒤 임시 스크립트 permission denied로 본 배치가 시작되지 않았다.
- 확인: 내부 Popen은 Orca 훅 식별 환경을 상속한다. Codex Stop 훅은 부모 pane으로 done을 전달할 수 있다. Python은 Orca 셸의 --no-daemon 래퍼도 우회한다. 해당 사건 SIGTERM 발신자는 미확인이다.
- 확인: Orca 임시 스크립트는 의도적으로 0600이며 `. path`로 읽는다. 업데이트 질문이 선행 입력을 소비한 경로는 추정이다. chmod는 하지 않는다.

|---|---|---|

| 일일 감독 | 기존 main.py → supervisor → 일일 자식 → 실행별 영수증 | PR #4 유지 |

| 응답 | 최종 응답 파일 → 기존 파싱·엄격 실패 처리 → 영수증·페이지·Git·Slack | 기존 경로 유지 |

인증·CODEX_HOME·PATH·사용자 설정·read-only sandbox·모델 gpt-6.1-sol은 유지한다. 재시도나 제한 시간은 바꾸지 않는다.

## 재발 방지와 검증

1. 모의 부모 환경을 넣는 회귀 테스트로 훅 식별자가 자식에 없고 인증·경로가 유지되는지 확인한다.
2. 전체 테스트와 독립 리뷰를 실행한다.
3. 실제 Orca 실행에서 내부 첫 호출 완료 뒤 외부 배치가 계속되는지, supervisor 종료와 동일 run_id의 영수증 및 게시 증거를 대조한다.
4. 재실행은 현재 날짜 기준 정상 배치로 한다. 과거 원자료가 없는 10월30일~11월1일 결과를 현재 피드로 위조하지 않는다. 누락 날짜 복구 여부는 별도 기록한다.
