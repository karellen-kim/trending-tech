# Slack 실패 진단 전달 보완 (#12)

목표: Git 게시 이후 Slack 요청이 실패해도 게시 성공 증거와 수신 불확실성을 최종 실행 요약에서 함께 확인한다.

근거: 2026-11-07 실행 794885d13c744f2cbadf6e229a1a2a7a는 Git 성공, Slack failed, exit 1이다. 이전 코드는 요청 오류 종류를 삭제했으므로 당시 네트워크 원인은 확정할 수 없다. HEAD d1792af는 이미 안전한 재시도와 비밀값 없는 오류 분류를 추가했다. 남은 문제는 supervisor.py의 출력 허용 목록이 새 진단 필드를 누락한다는 것이다.

입력·처리·출력 (기존 경로 내 한 목적 변경): notifier → RunReceipt의 Slack 단계(attempts=1, retry_wait_seconds=0, error_kind=read_timeout, delivery_state=unknown) → supervisor의 허용 필드 투영 수정 → daily_run_finished 요약에 같은 값 출력. Git 단계와 비정상 종료 판정은 기존대로 유지한다. webhook, 응답 본문, 원문 예외는 출력하지 않는다.

수정: 최종 요약의 허용 필드에 네 진단 필드를 추가한다. 자동 재발송이나 전체 일일 작업 재실행은 추가하지 않는다. 원본 영수증과 로그를 변경하지 않는다.

재발 방지: 실제 자식 프로세스가 notifier와 RunReceipt를 호출하는 테스트에서 ReadTimeout 실패와 ConnectTimeout 후 성공을 주입한다. 최종 요약의 진단 필드, Git 성공 보존, 종료 코드, 비밀값 차단을 검증한다. 허용 목록은 원문 예외와 webhook 필드를 계속 제외한다.

검증: 신규 테스트를 수정 전에 실행해 필드 누락을 재현하고, 수정 후 관련 테스트 및 전체 pytest를 실행한다. Slack 실전송은 수행하지 않는다. 외부 수신 여부는 이 테스트로 확정하지 않는다.

리스크: 출력에 필드 네 개가 추가된다. 기존 상태·종료 판정은 바뀌지 않으며 회귀 테스트로 확인한다. 문제가 생기면 허용 목록 변경만 되돌릴 수 있다.
