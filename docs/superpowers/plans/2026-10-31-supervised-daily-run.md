# 일일 실행의 최상위 종료 검증

## 목표와 확인된 현상

이슈 #3의 2026-10-30 실행은 Orca에서 completed였지만 업무 영수증은 interrupted/143이다.
23:55:23 KST에 시작해 23:55:49에 논문 선택을 호출했고 23:55:59에 취소됐다.
수집 이후의 요약·산출물·Git·Slack은 시작하지 않았다.
운영 main.py, summarizer.py, run_receipt.py는 현재 checkout과 바이트가 같다.
이전 병합 8040d50(#2)의 영수증 기록은 동작했다.

내부 Codex stdout/stderr는 이미 PIPE로 격리된다. 숫자 목록이 일반 콘솔로
누출됐다는 가설은 코드로 입증되지 않는다. 신호 발신자와 Orca의 completed 판정
근본 원인은 외부 이벤트가 없으므로 미확인이다.

이번 변경은 기존 `python -u main.py` 진입점에서 프로세스 종료와 같은 실행의
영수증을 함께 검증한다. 운영 등록을 바꾸지 않고 다음 호출부터 적용할 수 있게 한다.
실제 운영 배치·모델·게시 호출은 실행하지 않는다.

## 선택과 변경 흐름

콘솔 문구만 보강하면 프로세스 종료를 입증하지 못한다. 별도 선택 진입점은
현재 운영 경로에 적용되지 않는다. 따라서 기존 main.py 실행을 감독 부모로 만들고
기존 main()은 자식에서 그대로 호출한다. 직접 import한 main()의 계약은 유지한다.

| 단계 | 입력 → 처리 → 출력 | 변경·위치 |
| --- | --- | --- |
| 실행 시작 | 기존 main.py 명령 → 새 run_id와 실행 날짜 확정 → 자식 Python에 전달 | 수정: main.py __main__, 추가: supervisor.py |
| 업무 수행 | run_id → 기존 main() 수집·요약·게시 → logs/runs/<id>.json | 수정: main.main, RunReceipt에 선택 run_id |
| 로그 격리 | 자식 stdout/stderr → logs/runs/<id>.log → 감독 stdout에는 전달하지 않음 | 추가: supervisor.py |
| 종료 확인 | child.wait()의 OS 코드 + 같은 ID/PID 영수증 → 상태·단계·로그 경로 JSON | 추가: supervisor.py |

감독 결과는 자식 종료 전에는 출력하지 않는다. 영수증은 미리 생성한 ID의
정확한 경로에서만 읽고 run_id/PID/날짜/종료 시각/코드가 맞아야 한다.
published는 필수 단계 성공, Git pushed=true와 commit SHA, Slack HTTP 200,
미완료 LLM 부재를 확인한다. partial과 dry_run은 그대로 별도 상태로 보고한다.
failed/interrupted/running/없음/손상/불일치는 절대로 성공으로 바꾸지 않는다.
감독 SIGTERM/SIGINT는 자식에 전달해 종료까지 회수한다. 감독 중단도 성공이 아니다.
감독 종료 코드는 자식 비정상 코드를 보존하며, 자식이 0이어도 영수증 검증
실패이면 1이다. 감독이 받은 중단 신호는 128+신호 번호로 반환한다.
최종 JSON은 원문·예외 메시지 없이 실행 ID, 상태, 관측 코드, 업무 코드,
단계별 상태·게시 증거, 영수증·로그 경로를 포함한다.

## 재발 방지와 검증

- 테스트: 실제 가짜 자식이 숫자나 ready를 출력하고 대기해도 감독이 살아 있고 최종 stdout은 비어 있는지 확인한다.
- 테스트: 정상 게시, partial, dry_run, 실패, 자식/감독 SIGTERM, 영수증 없음·손상·다른 실행·PID·코드 불일치·미완료 LLM을 검증한다.
- 가드: published 상태 문자열만으로 성공하지 않고 동일 실행의 단계별 증거를 검증한다.
- 회귀: 내부 Codex의 stdout/stderr PIPE 계약, 기존 전체 pytest를 실행한다.

## 운영 제한과 롤백

감독 계층은 Orca가 중첩 Codex 이벤트를 수집하는 방식이나 completed 판정을
바꾸지 못한다. 외부 담당자가 원 실행의 23:55:57~59 KST 완료·프로세스 종료
이벤트를 대조해야 한다. 다음 자연 예약에서 감독 JSON, OS 종료와 같은 run_id의
영수증·필수 요약·산출물·Git·Slack 증거가 맞는지는 운영 검증으로 남긴다.
SIGKILL/호스트 장애로 감독 자체가 사라지면 최종 JSON이 없으므로 미완료다.
중단 시 이미 실행 중인 요약 스레드가 Codex의 600초 제한까지 남을 수 있다.
새 강제 종료 정책은 분리된 Codex 세션을 고아 프로세스로 만들 수 있어 추가하지 않는다.
감독은 대기 중에 성공을 출력하지 않으며 외부가 먼저 감독을 죽이면 최종 결과가 없다.
원본 로그·영수증은 보존하고, 문제가 있으면 코드만 이전 버전으로 되돌린다.
